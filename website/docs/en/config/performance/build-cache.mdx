# performance.buildCache

- **Type:**

```ts
type BuildCacheConfig =
  | boolean
  | {
      cacheDirectory?: string;
      cacheDigest?: Array<string | undefined>;
      buildDependencies?: string[];
    };
```

- **Default:** `false`
- **Version:** `>= 1.2.5`

To enable or configure persistent build cache.

When enabled, Rspack will store the build snapshots in the cache directory. In subsequent builds, if the cache is hit, Rspack can reuse the cached results instead of rebuilding from scratch, which can reduce the build time.

## Inspect cache diagnostics

Use `performance.buildCacheDiagnostics` to receive a report after each environment compilation, including rebuilds in watch mode:

```ts title="rsbuild.config.ts"
export default {
  performance: {
    buildCache: true,
    buildCacheDiagnostics(report) {
      console.log(report);
    },
  },
};
```

The report contains the environment name, compilation time, effective Rspack cache mode and persistent-cache settings, and entries from Rspack's `rspack.persistentCache` logger. Paths may appear in the settings, logs, and errors. `isWatch` identifies watch compilations. `isFirstCompile` follows the first compile cycle of the build across environments; neither field establishes whether the persistent cache was reused.

When Rspack provides structured cache information, `persistent.status` and `persistent.reason` contain its result. A `valid` status means that the metadata version and tracked build dependencies validated; it does not confirm that a snapshot or module entry was restored. Without structured information, recovery status is `unknown` and the reason is `null`. `persistent` is `null` for non-persistent cache modes.

When available, `moduleBuilds` contains `reused` and `total` counts from Rspack, captured immediately after `finishModules` and before sealing or optimization. `total` counts distinct modules in the main module graph, including modules that are ineligible for caching. `reused` counts modules whose build work was restored from cache and not rebuilt by that point. These counts measure graph module reuse, not cache lookup hits; they can include memory reuse as well as disk reuse. `moduleBuilds` is `null` when Rspack cannot provide a reliable count, including with older Rspack versions, unsupported modes, or a later rebuild or entry addition.

Reports serialize Rspack stats once per compilation, which adds overhead. If serialization fails, `statsError` contains the error and the build continues with an unknown recovery status. The callback can return a promise; Rsbuild waits for it before completing the compilation hook, and a thrown or rejected callback fails the hook.

## Enable cache

Setting `performance.buildCache` to `true` will enable the persistent build cache:

```ts title="rsbuild.config.ts"
export default {
  performance: {
    buildCache: true,
  },
};
```

Or only enable cache in development mode:

```ts title="rsbuild.config.ts"
const isDev = process.env.NODE_ENV === 'development';

export default {
  performance: {
    buildCache: isDev,
  },
};
```

## Options

### cacheDirectory

- **Type:** `string`
- **Default:** `node_modules/.cache`

Set the output directory of the cache files.

```ts title="rsbuild.config.ts"
import path from 'node:path';

export default {
  performance: {
    buildCache: {
      cacheDirectory: path.resolve(__dirname, 'node_modules/.my-cache'),
    },
  },
};
```

### cacheDigest

- **Type:** `Array<string | undefined>`
- **Default:** `undefined`

Add additional cache digests, the previous build cache will be invalidated when any value in the array changes.

`cacheDigest` allows you to add variables that affect the build result, for example `process.env.SOME_ENV`.

```ts title="rsbuild.config.ts"
export default defineConfig({
  performance: {
    buildCache: {
      cacheDigest: [process.env.SOME_ENV],
    },
  },
});
```

### buildDependencies

- **Type:** `string[]`

`buildDependencies` is an array of additional code dependencies for the build. Rspack will use a hash of each of these items and all dependencies to invalidate the filesystem cache.

Equivalent to Rspack's [cache.buildDependencies](https://rspack.rs/config/cache#builddependencies) option.

#### Default value

Rsbuild will use the following configuration files as the default build dependencies:

- `package.json`
- `tsconfig.json`
- `.env`, `.env.*`
- `.browserslistrc`
- `tailwindcss.config.*`

Additionally:

- When using Rsbuild CLI, it will also automatically add the Rsbuild configuration file (`rsbuild.config.*`) to the build dependencies.
- When using Rsbuild's [loadConfig](/api/javascript-api/core#loadconfig) JS API, it will also automatically add the configuration file path to the build dependencies.

#### Example

When you add other build dependencies, Rsbuild merges these custom dependencies with the default dependencies and passes them to Rspack.

```ts title="rsbuild.config.ts"
export default {
  performance: {
    buildCache: {
      buildDependencies: [__filename],
    },
  },
};
```
