# server.allowedHosts

- **Type:** `string[] | true`
- **Default:** `true`

Control which hostnames can access the dev server through HTTP or WebSocket requests. This option also applies when HTTPS is enabled. It does not currently apply to the preview server.

- `true`: disable Host validation and accept any hostname.
- `[]`: allow `localhost`, subdomains of `.localhost`, IP addresses, and the hostname configured by [server.host](/config/server/host) or `--host`.
- `string[]`: also allow the specified hostnames. An entry starting with `.` allows both the hostname itself and all its subdomains. For example, `.example.test` allows `example.test` and `app.example.test`.

Entries should contain hostnames only, without a protocol, port, or path. Matching is case-insensitive and ignores a trailing dot. Request ports do not affect matching.

```ts title="rsbuild.config.ts"
export default {
  server: {
    allowedHosts: ['app.example.test', '.internal.example.test'],
  },
};
```

`server.host` controls which network interface the server listens on; `server.allowedHosts` checks the hostname in incoming requests. Listening on `0.0.0.0` or `::` does not allow arbitrary hostnames when Host validation is enabled.

Requests with a missing, invalid, or disallowed Host receive a `403` response before user middleware, proxy requests, or HMR connections are handled. HTTP/2 requests are checked using `:authority`; conflicting `Host` and `:authority` headers are rejected. Forwarded headers such as `X-Forwarded-Host` are not used for validation.

In middleware mode, validation applies to requests handled by Rsbuild's middleware and WebSocket handler. Routes and upgrade listeners managed separately by your application need their own validation.

:::warning
Allow only hostnames you control. Keeping `allowedHosts: true` disables protection against DNS rebinding attacks, which can expose dev server content to malicious websites. Host validation does not replace authentication or [CORS configuration](/config/server/cors).
:::
