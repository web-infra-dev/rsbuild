# server.allowedHosts

- **Type:** `string[] | true`
- **Default:** `true`

Specify which hostnames the dev and preview servers accept in HTTP and WebSocket requests.

## Usage

Host validation is disabled by default. Set this option to an array to enable it:

- `true`: disable validation and accept any hostname.
- `[]`: allow only `localhost`, its subdomains (such as `app.localhost`), IP addresses, and the hostname set by [server.host](/config/server/host) or `--host`.
- `string[]`: allow additional hostnames alongside those listed above.

Allow a specific hostname without its subdomains:

```ts title="rsbuild.config.ts"
export default {
  server: {
    allowedHosts: ['app.example.test'],
  },
};
```

To allow a domain and all its subdomains, add a leading `.`:

```ts title="rsbuild.config.ts"
export default {
  server: {
    // Allows example.test, app.example.test, a.b.example.test, etc.
    allowedHosts: ['.example.test'],
  },
};
```

Use hostnames without a protocol, port, or path. For example, use `app.example.test`, not `https://app.example.test:3000/`. Matching is case-insensitive and ignores a trailing dot. The port in a request does not affect hostname matching.

:::warning
Only allow domains whose DNS records you control or whose owners you trust. Do not allow broad suffixes such as `.com`, which would also allow domains owned by others.

Setting `allowedHosts: true` disables Host validation and can leave server content exposed to DNS rebinding attacks. Use `[]` or a list of trusted hostnames to enable protection. Host validation does not replace authentication or [CORS configuration](/config/server/cors).
:::

## Difference from server.host

[server.host](/config/server/host) determines the network address the server listens on. `server.allowedHosts` determines which hostnames it accepts in requests.

For example, `host: '0.0.0.0'` lets the server listen on all IPv4 interfaces. With `allowedHosts: ['app.example.test']`, it accepts requests for `app.example.test` in addition to the automatically allowed hosts, and rejects requests for other hostnames.

## Request validation

When validation is enabled, requests with a missing, invalid, or disallowed hostname receive a `403 Forbidden` response. The check runs before custom middleware, proxy forwarding, and HMR connections.

Rsbuild reads the hostname from `Host` in HTTP/1.1 requests and from `:authority` in HTTP/2 requests. Requests with conflicting `Host` and `:authority` values are rejected. Forwarded headers such as `X-Forwarded-Host` do not affect this check.

In dev server middleware mode, Rsbuild checks requests that reach its middleware or WebSocket handler. Your application is responsible for checking any routes or WebSocket connections it handles separately.
