# server.publicDir

- **Type:**

```ts
type PublicDirOptions = {
  name?: string;
  copyOnBuild?: boolean | 'auto';
  ignore?: string[];
  watch?: boolean;
};
type PublicDir = false | PublicDirOptions | PublicDirOptions[];
```

- **Default:**

```js
const defaultValue = {
  name: 'public',
  copyOnBuild: 'auto',
  ignore: [],
  watch: false,
};
```

By default, Rsbuild uses the `public` directory for serving public assets. Files in this directory are served at [server.base](/config/server/base) path (default `/`).

> Related document: [Public Folder](/guide/basic/static-assets#public-folder).

## Options

### name

- **Type:** `string`
- **Default:** `'public'`

The name of the public directory. The value of `name` can be set to a relative path or an absolute path. Relative path will be resolved relative to the project root directory.

- Relative path example:

```ts title="rsbuild.config.ts"
export default {
  server: {
    publicDir: {
      name: '../some-public',
    },
  },
};
```

- Absolute path example:

```ts
import path from 'node:path';

export default {
  server: {
    publicDir: {
      name: path.join(__dirname, '../some-public'),
    },
  },
};
```

:::tip
We do not recommend setting `name` to the source code directory (such as `src`). Since the public directory will be copied to the output directory during production builds, this may introduce a risk of unintentionally exposing source code.

If you do need to use that directory, set [copyOnBuild](#copyonbuild) to `false` to prevent those files from being included in the build output.
:::

### copyOnBuild

- **Type:** `boolean | 'auto'`
- **Default:** `'auto'`

Whether to copy files from the public directory to the dist directory on production build.

- `true`: copy files.
- `false`: do not copy files.
- `'auto'`: if [output.target](/config/output/target) is not `'node'`, copy files, otherwise do not copy.

:::tip
During dev builds, if you need to copy some static assets to the output directory, you can use the [output.copy](/config/output/copy) option instead.
:::

#### Disable

For example, disable `copyOnBuild`:

```ts title="rsbuild.config.ts"
export default {
  server: {
    publicDir: {
      copyOnBuild: false,
    },
  },
};
```

Note that setting the value of `copyOnBuild` to false means that when you run `rsbuild preview` for a production preview, you will not be able to access the corresponding static resources.

#### Node target

By default, when [output.target](/config/output/target) is `'node'`, Rsbuild will not copy files from the public directory.

You can set `copyOnBuild` to `true` to copy files for the `node` target:

```ts title="rsbuild.config.ts"
export default {
  output: {
    target: 'node',
  },
  server: {
    publicDir: {
      copyOnBuild: true,
    },
  },
};
```

### ignore

- **Type:** `string[]`
- **Default:** `[]`

Glob patterns for files or directories to ignore when copying the public directory during production builds.

This option only affects the copy behavior during build. It does not affect static file serving in the dev server.

For example, ignore `foo.js` when copying the public directory:

```ts title="rsbuild.config.ts"
export default {
  server: {
    publicDir: {
      ignore: ['**/foo.js'],
    },
  },
};
```

### watch

- **Type:** `boolean`
- **Default:** `false`

Whether to watch the public directory and reload the page when the files change.

Setting `watch` to `true` allows the dev server to watch changes to files in the specified public directory and reload the page when the files are changed:

```ts title="rsbuild.config.ts"
export default {
  server: {
    publicDir: {
      watch: true,
    },
  },
};
```

Note that the `watch` option is only valid in development mode. If [dev.hmr](/config/dev/hmr) and [dev.liveReload](/config/dev/live-reload) are both set to false, `watch` will be ignored.

## Multiple directories

The `server.publicDir` can be configured as an array, allowing you to serve multiple directories as static assets folders:

```ts title="rsbuild.config.ts"
export default {
  server: {
    publicDir: [
      {
        name: 'public',
      },
      {
        name: 'assets',
        watch: false,
      },
    ],
  },
};
```

## Disabled

You can set `publicDir` to `false` to disable the static assets serving:

```ts title="rsbuild.config.ts"
export default {
  server: {
    publicDir: false,
  },
};
```

## Multiple environments

### Directory configuration

- **Version:** `>= 2.3.0`

Configure `server.publicDir` under `environments` to use different public directories for each environment. Environments without this option use the global setting. Set it to `false` to disable public directories for an environment.

```ts title="rsbuild.config.ts"
export default {
  environments: {
    client: {},
    admin: {
      server: {
        publicDir: {
          name: 'public-admin',
        },
      },
    },
    worker: {
      server: {
        publicDir: false,
      },
    },
  },
};
```

In this example, `client` uses `public`, `admin` uses `public-admin`, and `worker` has no public directory.

An environment's `publicDir` replaces the global value entirely. Omitted options use their defaults rather than inheriting the global settings. For example, `{ copyOnBuild: false }` uses the default directory name `public`, even if the global configuration specifies a different directory. You can also configure an environment's public directory when the global `publicDir` is `false`.

### Build behavior

During production builds, Rsbuild copies each environment's public files to its output directory according to its `copyOnBuild` and `ignore` settings.

For example, if two web environments both use the default `public` directory, a file at `public/logo.png` is copied to the following locations:

| Output directories        | Copied files                                                     |
| ------------------------- | ---------------------------------------------------------------- |
| `dist` and `dist/web1`    | Only `dist/logo.png`, with no extra copy at `dist/web1/logo.png` |
| `dist/esm` and `dist/cjs` | Both `dist/esm/logo.png` and `dist/cjs/logo.png`                 |

Skipping the extra copy in a nested output directory only applies when the environments have the same public directory list, in the same order, with matching `copyOnBuild` and `ignore` settings. If the environments use different public directories or copy settings, Rsbuild copies their files separately, even when one output directory is inside the other.

### Dev server

During development, all environments share one dev server, which serves their public files together. For the example above, files from both `public` and `public-admin` are accessible, even though `worker` has `publicDir: false`.

- If directories contain files with the same URL, the server returns the first match. It checks environments in configuration order and directories within each environment in array order.
- If multiple environments use the same directory, setting `watch: true` in any one of them enables file watching and page reloads for that directory.
