# performance.buildCache

- **类型：**

```ts
type BuildCacheConfig =
  | boolean
  | {
      cacheDirectory?: string;
      cacheDigest?: Array<string | undefined>;
      buildDependencies?: string[];
    };
```

- **默认值：** `false`
- **版本：** `>= 1.2.5`

用于启用或配置持久化构建缓存。

当启用时，Rspack 会在缓存目录中存储构建快照。在后续的构建中，如果命中缓存，Rspack 可以重用缓存的结果，而不是从头开始重新构建，这可以显著减少构建时间。

## 查看缓存诊断信息

使用 `performance.buildCacheDiagnostics` 可以在每个环境编译完成后接收报告，包括监听模式下的重新编译：

```ts title="rsbuild.config.ts"
export default {
  performance: {
    buildCache: true,
    buildCacheDiagnostics(report) {
      console.log(report);
    },
  },
};
```

假设项目只有两个模块，你修改了其中一个源文件。Rspack 可能报告 `persistent.status: 'valid'`，表示缓存版本和跟踪的构建依赖仍然匹配；同时报告 `moduleBuilds: { reused: 1, total: 2 }`，表示复用了其中一个模块的构建结果。

- `persistent` 描述本次编译的缓存验证结果。使用旧版 Rspack 时，状态为 `unknown`；未使用持久化缓存时，此字段为 `null`。
- `persistentSessionInitialization` 描述 Rspack 打开共享文件系统缓存时的验证结果。后续编译可能报告相同的初始结果。Rspack 未提供会话验证结果时，此字段为 `null`。
- `moduleBuilds` 在 `finishModules` 后统计主模块图中不同的模块，包括不能缓存的模块。复用的构建结果可能来自内存或磁盘。复用数为零表示未复用任何模块；`null` 表示无法统计。

报告还包含环境名称、编译耗时和 Rspack 规范化后的持久化缓存配置。配置和错误可能包含文件路径。禁用缓存或使用内存缓存时，Rsbuild 会跳过统计信息的收集。

如果读取缓存统计信息失败，构建会继续，错误信息保存在 `statsError` 中。Rsbuild 会等待回调完成，回调抛出错误或返回 rejected Promise 会使编译钩子失败。

如需查看原始日志，旧版缓存使用 Rspack 的 `stats.loggingDebug: /^rspack\.persistentCache$/`，新版文件系统缓存使用 `rspack.cache.IdleFileCache` 基础设施日志记录器。

## 启用缓存

设置 `performance.buildCache` 为 `true` 将启用持久化构建缓存：

```ts title="rsbuild.config.ts"
export default {
  performance: {
    buildCache: true,
  },
};
```

或者仅在开发模式下启用缓存：

```ts title="rsbuild.config.ts"
const isDev = process.env.NODE_ENV === 'development';

export default defineConfig({
  performance: {
    buildCache: isDev,
  },
});
```

## 选项

### cacheDirectory

- **类型：** `string`
- **默认值：** `node_modules/.cache`

用于设置缓存文件的输出目录。

```ts title="rsbuild.config.ts"
import path from 'node:path';

export default {
  performance: {
    buildCache: {
      cacheDirectory: path.resolve(__dirname, 'node_modules/.my-cache'),
    },
  },
};
```

### cacheDigest

- **类型：** `Array<string | undefined>`
- **默认值：** `undefined`

添加额外的缓存摘要，当数组中的任何值发生变化时，之前的构建缓存就会失效。

`cacheDigest` 可以用于添加一些会对构建结果产生影响的变量，例如 `process.env.SOME_ENV`。

```ts title="rsbuild.config.ts"
export default {
  performance: {
    buildCache: {
      cacheDigest: [process.env.SOME_ENV],
    },
  },
};
```

### buildDependencies

- **类型：** `string[]`

`buildDependencies` 是一个包含构建依赖的文件数组，Rspack 将使用其中每个文件的哈希值来判断持久化缓存是否失效。

等价于 Rspack 的 [cache.buildDependencies](https://rspack.rs/zh/config/cache#builddependencies) 选项。

#### 默认值

Rsbuild 会将以下配置文件作为默认的构建依赖：

- `package.json`
- `tsconfig.json`
- `.env`, `.env.*`
- `.browserslistrc`
- `tailwindcss.config.*`

此外：

- 在使用 Rsbuild CLI 时，它会自动将 Rsbuild 配置文件（`rsbuild.config.*`）添加到构建依赖中。
- 在使用 Rsbuild 的 [loadConfig](/api/javascript-api/core#loadconfig) JS API 时，它会将配置文件的路径添加到构建依赖中。

#### 示例

当你添加其他构建依赖时，Rsbuild 会将这些自定义依赖与默认依赖合并，并传递给 Rspack。

```ts title="rsbuild.config.ts"
export default {
  performance: {
    buildCache: {
      buildDependencies: [__filename],
    },
  },
};
```
